# SmAIltalk(スマイルトーク)

## これは何か

「こういうものが欲しい」と言葉で伝えると、AI が変更案(差分)を作り、あなたが中身を確かめてから適用する ——
その繰り返しで、データベース付きの業務用ツールを1本ずつ組み立て、**データを入れたまま育て続ける**ためのソフトウェアです。
プログラムを書き出すのではなく、アプリの定義そのものを保存し、画面はその定義を読んで毎回描き直します。
そのため、動いているアプリの定義がそのまま仕様書を兼ねます。

---

## 何ができるか

- **表を作り、項目を足し、画面を作る。** 一覧・詳細・入力フォームを、定義を足すだけで用意できます。
- **定義を変えたら、ブラウザのリロードだけで新しい画面になります。** 作り直しもサーバの再起動も要りません。
- **ログインと権限。** 運営側の役割(閲覧 / 編集 / 管理)と、アプリが自分で名付けた利用者の種類を扱えます。
  「この画面はこの役割にだけ見せる」「この項目はこの役割にだけ見せる」を定義に書けます。
- **自動処理。** 「登録されたとき」「更新されたとき」「決まった時刻に」を起点に、同じアプリの表へ書き込めます。
- **計算。** 小さな関数を1つの島として持ち込み、値を計算して表に書き戻せます。
- **集計表とグラフ。** 表を集計した画面を定義できます。
- **外部への送信・受信、AI 呼び出し。** ただし成立させるには人間(持ち主)の許可が要ります(下の「何ができないか」)。
- **取り消し。** 適用の直前を丸ごと保存しており、そこへ巻き戻せます(ただし射程に注意。下記)。
- **見た目。** アプリ単位の配色・書体・余白をまとめて指定でき、画面ごとの見せ方も決められた選択肢から選べます。

### 書けるものの全量

ここに並べた名前が全量です。**この一覧に無い名前は、言い換えても書けません。**

- **扱えるもの**: `app` / `table` / `form` / `list_view` / `detail_view` / `workflow` / `function` / `report_view`
- **項目の型**: `text` / `long_text` / `number` / `boolean` / `date` / `select` / `reference` / `image` / `file`
- **定義を変える操作**: `add_table` / `add_field` / `add_view` / `update_view` / `remove_field` / `remove_table` /
  `change_table` / `change_field` / `remove_view` / `add_workflow` / `update_workflow` / `remove_workflow` /
  `add_function` / `update_function` / `remove_function` / `set_theme` / `set_roles`

手元の定義ファイルがこの語彙に収まっているかは、その場で確かめられます。

```bash
bun run validate fixtures/valid/book-tracker.json
bun run validate path/to/file.json --json   # 機械可読な形で出す
```

語彙から外れると、外れた位置と許される値が返ります(実際の出力です)。

```
NG: fixtures/invalid/unknown-field-type.json の検証に失敗しました(マニフェスト、エラー1件)。
/app/tables/0/fields/1/type: type の値 "email" は語彙にありません。 許可される値: text / long_text / number / boolean / date / select / reference / image / file ヒント: 許可される値のいずれかに置き換えてください。v0の語彙は拡張できません。
```

## 何ができないか

**これで何でも作れるわけではありません。** 隠さずに書きます。

- **自由な見た目は作れません。** AI が CSS を書き込める場所はありません。ピクセル座標も、絶対配置も、重ね順も指せません。
  画面ごとの配色も、ダークモードの指定もありません。持ち主が自分で CSS を用意して発行したときだけ、宣言した画面に効きます。
- **自動処理の条件は「等しいか」だけです。** 「より大きい」「より小さい」といった大小比較も、かつ / または / そうでなければ /
  入れ子 / 計算式も書けません(例外は「date の項目が N 日以上前の行だけを対象にする」という時刻専用の形ひとつです)。
- **自動処理は途中で諦められません。** アクションが1つでも失敗すると、それを起こしたレコードの書き込みごと巻き戻ります。
  「この処理だけは失敗しても無視する」という宣言はありません。
- **外部への送信を AI が勝手に成立させることはできません。** 送信先への接続を発行できるのは人間(持ち主)だけで、
  AI にできるのは申請までです。許可の無い送信、許可された宛先の外への送信は、説明の上ではなく実行の層で止まります。
- **取り消しは「差分の巻き戻し」ではありません。** 適用直前の状態へデータベース全体を書き戻す操作です。
  **その適用より後に入力されたデータは、取り消すと一緒に消えます。** 消した項目の値だけを選んで戻すことはできません。
  何が失われるかは、実行前に実測して見せる道具があります。必ずそれを見てから決めてください。
- **戻せない操作があります。** レコードの更新・削除と、アプリごとの削除は履歴に残らず、取り消しの対象になりません。
- **汎用のプログラミング環境ではありません。** 上の語彙に無い概念(たとえば任意のクエリ言語、任意の画面遷移、
  任意の外部ライブラリ)は持ち込めません。
- **公開サーバとして運用する前提の作りではありません。** 既定では手元のマシンだけで待ち受けます。

## 動かすのに要るもの

- **[Bun](https://bun.com/)**。動作を確かめている版は `1.3.14` です。
- **ブラウザ**(作ったアプリを開くため)。
- **AI から操作したい場合は [Claude Code](https://claude.com/claude-code)**。会話の口はここが担い、この製品は道具箱だけを出します。

インターネット接続は、依存パッケージを取得するときにだけ要ります。アプリの動作そのものは手元で完結します。

## 最初の一歩

```bash
bun install                 # 依存パッケージを入れる
bun run build:web           # 画面をビルドする(飛ばすと開いても 404 になります)
ST_AUTH_EXPECTED_ORIGIN=http://localhost:3000 bun run server
```

起動すると、待ち受け先とデータの置き場が1行で出ます。

```
smailtalk server: http://127.0.0.1:3000 (dataRoot=data, timeZone=Asia/Tokyo)
```

ブラウザで **`http://localhost:3000`** を開きます。

- **`localhost` で開いてください。** 数字の `127.0.0.1` で開くと、ログインの仕組みが受け付けません。
- **`ST_AUTH_EXPECTED_ORIGIN` を忘れないでください。** 書き込みを受け付ける出所の既定値は、
  開発用サーバの `http://localhost:5173` です。合っていないと、画面は出るのに保存だけが黙って弾かれます。
- **最初に登録した人が、そのアプリの持ち主(管理者)になります。** ここは自分で登録してください。
  先に AI に登録させると、あなたが管理者になれません。

画面に手を入れながら開発したい場合は、API と画面を別々に起動します(この形なら `http://localhost:5173` を開きます)。

```bash
bun run dev:server          # 片方のターミナル
bun run dev:web             # もう片方のターミナル
```

そのほかに用意してあるコマンドです。

| コマンド | 内容 |
|---|---|
| `bun run server` | HTTP API と画面を1つのプロセスで動かす(既定 `http://127.0.0.1:3000`) |
| `bun run dev:server` | API を変更監視つきで動かす |
| `bun run dev:web` | 画面の開発用サーバを動かす(既定 `http://localhost:5173`。**`http://127.0.0.1:5173` では繋がりません** —— このサーバは IPv6 のループバックだけを待ち受けます) |
| `bun run build:web` | 画面を `web/dist` にビルドする |
| `bun run preview:web` | ビルドした画面をそのまま確認する |
| `bun run validate <file>` | 定義ファイル / 差分ファイルが語彙に収まっているか検証する |
| `bun run requirements-doc --data-root data --app <app_id>` | 動いているアプリの定義から要件の文書を組み立てる |
| `bun run mcp` | AI から使う口を、標準入出力で起動する |
| `bun run mcp:http` | 同じ口を HTTP で起動する |
| `bun run test:e2e` | 実ブラウザでの通し確認を走らせる |

`bun run validate` は、通れば `0`、語彙から外れていれば `1`、そもそも読めなければ `2` で終わります。

## AI から使う口(MCP サーバ)

本来の使い方は、**AI との会話だけでアプリを作って育てる**ことです。
専用のチャット画面は作らず、この製品は道具箱を出すだけで、言葉を解釈する側は Claude Code に任せています。

このフォルダの直下に `.mcp.json` を置き、そこで `claude` を起動すると、プロジェクトの道具箱として見つかります
(初回は承認を聞かれます)。

```json
{
  "mcpServers": {
    "smailtalk": {
      "command": "bun",
      "args": ["run", "src/mcp/index.ts"],
      "env": {
        "ST_DATA_ROOT": "data",
        "ST_PREVIEW_BASE_URL": "http://localhost:3000",
        "ST_MCP_ACTOR": "あなたのログイン名"
      }
    }
  }
}
```

繋がったかは `claude mcp list` で確かめられます。

### 先に知っておくと詰まらないこと

- **`ST_MCP_ACTOR` は必ず埋めてください。** ここが空だと、道具の呼び出しはすべて失敗します。
  アプリを名指しして触る道具は、この名前が**そのアプリに登録済みの利用者であること**まで要求します。
  だから、まずブラウザで自分を登録し、そのログイン名をここに書きます。
- **書き換えたら、AI 側を起動し直してください。** この名乗りは繋いだ時に一度だけ読まれます。
- **画面を出すサーバと、この口は別のプロセスです。** 状態は `ST_DATA_ROOT` が指す同じ置き場を通じてだけ共有します。
  ここが食い違うと、「アプリは作れたのに画面に何も出ない」という状態になります。
  どちらも既定では**起動したときの現在地の直下の `data`** を見るので、**同じ場所から起動**してください。

### 出している道具

- **読むもの**: `list_apps` / `get_manifest` / `get_changelog` / `get_preview_url` / `list_records` / `read_report` /
  `report_drift` / `preview_undo` / `preview_redo` / `dry_run_diff` / `generate_requirements_doc`
  - **【2026-08-25 追記】読むものの中で `dry_run_diff` だけは、`apply_diff` と
    同じ権限(役割の規則の `target: "app"` / `can: ["write"]`)を要求します。**
    **役割の規則を1本も書いていないアプリでは、持ち主でも断られます**
    (`set_roles` でその1行を書き戻してください)。
    **他の読むものには、この壁は掛かっていません。**
- **変えるもの**: `create_app` / `delete_app` / `apply_diff` / `undo` / `redo` / `insert_sample_data` /
  `write_records` / `update_record` / `delete_record` / `request_connection` / `request_ai_capability` /
  `request_custom_css` / `request_inbound_endpoint`

名前が `request_` で始まるものは**申請**です。呼んでも外部との接続が成立するわけではなく、
人間が発行して初めて効きます。

### AI 向けの説明書を入れる

道具の説明とは別に、**AI が必要になったときだけ開く説明書**を同梱してあります(差分の形 / 画面の形 / 自動処理の形 /
アプリの作り方)。入れる前に、形だけをその場で確かめられます。

**同梱している説明書は今日 4本です**(`plugins/smailtalk/skills/` の下に実在するディレクトリの数と一致します)。
**本数が変わったら、この1文もその場で書き換えてください** —— 名前の列挙(上の段落)を増減させただけでは、この行だけが古いまま残ります。

```bash
claude plugin validate ./plugins/smailtalk --strict
claude plugin validate ./.claude-plugin/marketplace.json --strict
```

入れるときは、Claude Code の中で2つ打ちます(`<path>` はこのフォルダのパス)。

```
/plugin marketplace add <path>
/plugin install smailtalk@smailtalk-plugins
```

入れても入れなくても、道具箱の繋ぎ方は変わりません。効くのは Claude Code だけで、ほかの相手には読まれません。

## 中に入っているもの

| パス | 内容 |
|---|---|
| `src/kernel/` | 中核。定義の持ち方・解釈・保存・適用と取り消し。手書きの普通のコードで、育てない層 |
| `src/server/` | HTTP API と、ビルドした画面の配信 |
| `src/mcp/` | AI から使う口(道具箱) |
| `src/auth/` | ログイン・セッション・役割と権限 |
| `src/cli/` | コマンド(`validate` など)。中核の公開機能を呼ぶだけの薄い層 |
| `src/shared/` | 上のいくつかで共有する小さな部品 |
| `web/` | ブラウザ側。アプリごとの作り分けは無く、汎用の部品が定義を読んで描きます |
| `schemas/` | 語彙の正準(JSON Schema) |
| `fixtures/` | 検証用のサンプル定義。通るもの・弾かれるものの両方 |
| `plugins/` | AI 向けの説明書(同梱の配布物) |
| `templates/` | あなたの作業フォルダに置く雛形 |
| `scripts/` | 開発と検証に使う補助。動かすのに必須ではありません |
| `Dockerfile` / `docker/` | 実行専用の器を組むための材料(組み立て方はこの案内の範囲外です) |
| `data/` | 実行時のデータ。バージョン管理の対象外 |

アプリの実体は `data` の下に置かれます。置き場は `ST_DATA_ROOT` で差し替えられ、既定は現在地の直下の `data` です。

```
data/
├── kernel.sqlite                    … アプリの台帳と変更履歴
└── apps/
    └── <app_id>/
        ├── manifest.json            … このアプリの定義(正)
        ├── app.sqlite               … このアプリのデータ(1アプリ=1ファイル)
        └── snapshots/
            └── <連番>-<diff_id>/    … 適用の直前に取った manifest.json と app.sqlite
```

定義とデータが同じ場所に並ぶので、**この2つのファイルをコピーすればそのまま完全な控え**になり、
取り消しはその逆のコピーで済みます。

## もっと詳しく知るには

このフォルダに、続きが3本あります。

| ファイル | 読むとき |
|---|---|
| `TUTORIAL.md` | **まずこれ。** 何も無いところから、通しで1本作り終えるまでを手順で辿ります |
| `MANUAL.md` | 書ける語彙と操作の全量、注意すべき挙動、できないことを引くとき |
| `templates/CLAUDE.md` | あなたの作業フォルダに置いて、**あなたの AI に読ませる**雛形。作業の進め方と、守らせたい約束が書いてあります |
