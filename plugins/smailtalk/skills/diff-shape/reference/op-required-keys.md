## `changes` を取るのは3つだけ

`changes` の中に書けるキーは、`op` によって別の集合になる。

| `op` | `changes` に書けるキー |
|---|---|
| `change_table` | `id`, `name`, `representative_field`, `reference_search_fields`, `access_control`(**5つだけ**) |
| `change_field` | `id`, `name`, `type`, `required`, `options`, `reference_table`, `unique`, `unit`, `emphasis`, `hide_when_empty`, `reference_picker`, `reference_search_fields`(**12個だけ**) |
| `update_view` | 27個。一覧は view-shape の説明書の参照ファイルにある |

**【`V8-M20` で 13 → 12 になった】** **`writable_by`(書ける相手)が撤去された。**
**同じ節にあった「`change_field` の `changes` に `audience` は書けない」も、今日は
言うまでもない** —— **`audience` というキーはフィールド定義そのものから消えたので、
`add_field` / `add_table` でも書けない。**
**書ける相手・見せる相手は役割の規則(`app.roles[].rules`)に書く**(下の `set_roles` の節)。

## テーブル・フィールドの定義

| 定義 | 必須キー | 書けるキーの全量 |
|---|---|---|
| `table` | `id`, `name`, `fields` | `id`, `name`, `fields`, `representative_field`, `reference_search_fields`, `access_control` |
| `field` | `id`, `name`, `type` | `id`, `name`, `type`, `required`, `options`, `reference_table`, `unique`, `unit`, `emphasis`, `hide_when_empty`, `reference_picker`, `reference_search_fields` |

**【`V8-M20` で 14 → 12 になった】** **フィールド定義から `audience`(見せる相手)と
`writable_by`(書ける相手)が撤去された。** どちらも役割の規則に置き直されている。

**型ごとに増える必須キー**:

- `type: "select"` → `options` が必須
- `type: "reference"` → `reference_table` が必須

## 参照項目の2キー(名前だけでは意味が取れないので書く)

**どちらも `reference` 型の項目にだけ書ける。**他の型に書くと差分全体が拒否される。
**`change_field` の `changes` にも書けて、値は実際に適用後のマニフェストに残る。**

| キー | 何を決めるか | 書ける値 |
|---|---|---|
| `reference_picker` | **この項目を画面でどう選ばせるか** | `list`(一覧から選ぶ。既定)/ `type_filter`(打った文字で絞る)/ `search`(別の面を開いて探す)の**3つだけ** |
| `reference_search_fields` | **候補を探すとき、打った文字を照合する列** | 参照先テーブルに実在する `text` / `long_text` のフィールドIDの配列。**1本以上8本以下・重複不可** |

```json
{ "op": "change_field", "table": "invoices", "field": "partner",
  "changes": { "reference_picker": "search", "reference_search_fields": ["name", "kana"] } }
```

**先に知っておくこと**:

- **4つ目の選び方は無い。** 器の名前(小窓など)も、候補の上限件数も、打つたびの取り直しの間隔も1つも書けない —— **どれもプラットフォームが決めて固定である。**
- **役割の規則(`app.roles[].rules`)が `target: "field"` で名指しした項目は `reference_search_fields` に書けない** —— 絞り込みの当たり外れが、隠した項目の値の手がかりになるためである。**【`V8-M20` で置き直された】旧文は「`audience`(見せる相手)を宣言した項目は書けない」だった** —— そのキーは撤去されたので、同じ問いを役割の規則について問い直している(判定は `can` を見ず、名指しの有無だけを見る)。
- **照合は部分一致を `or` で結んだ形に固定である。** 前方一致・正規表現・あいまい検索・複数語の AND は1つも無い。
- **`table` の側にも同じ名前の `reference_search_fields` がある。** そちらは「このテーブルが参照されたときの既定」で、
  項目の側はその上書きである(**優先順位は 項目 > テーブル > 代表の項目1本**)。**画面ごとには変えられない。**
- **どちらも全置換で、前進では外せない** —— 外すには `undo` で戻すか、作り直す。
- **選び方を入力画面ごとに変える口は、画面の側の `reference_pickers` である**(→ view-shape の説明書)。

## ID の形

`^[a-z][a-z0-9_-]*$` に一致する 1〜64文字の文字列。
**先頭は英小文字**でなければならず、大文字・日本語・空白・記号(`_` と `-` を除く)は使えない。
`diff_id` だけはさらに **59文字以内**(undo が `undo-<diff_id>` を作るため)。

## この参照ファイルが持っていないもの

- **画面(`view`)の中身**(`type` ごとの必須キー・書けないキー・`preset_` の値域)。
  → view-shape の説明書にある。
- **ワークフローと関数の中身**(`trigger` / `actions` / `input` / `output`)。
  → automation-shape の説明書にある。
- **テーマの25スロットの名前**。この説明書は1つも列挙していない。
