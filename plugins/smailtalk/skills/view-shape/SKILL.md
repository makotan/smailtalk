## 3a. 「見せる相手」は画面ではなく役割の規則に書く(`set_roles`)

**画面・項目・ボタンを誰に見せるかは、画面定義にも項目定義にも書かない。**
**`app.roles[].rules` に書き、差分操作は `set_roles`(全置換)である。**

```json
{ "op": "set_roles",
  "roles": [
    { "id": "owner",  "name": "管理" },
    { "id": "editor", "name": "編集" },
    { "id": "viewer", "name": "閲覧",
      "rules": [
        { "target": "view",  "view": "task_list", "can": ["read"] },
        { "target": "field", "table": "task", "field": "cost", "can": ["read"] },
        { "target": "table", "table": "task", "can": ["read", "write"],
          "when": { "and": [ { "field": "state", "equals": "doing" },
                             { "field": "assignee", "equals_current_user": true } ] } }
      ] }
  ] }
```

| 対象(`target`) | 一緒に必須 | 書ける `can` | `when` |
|---|---|---|---|
| `table` | `table` | `read` / `write` / `delete` | 書ける |
| `field` | `table`, `field` | `read` / `write` | 書ける |
| `view` | `view` | `read` だけ | **書けない** |
| `action` | `view`, `action` | `read` だけ | **書けない** |

- **`target` と `can` はどの規則でも必須。** 対象4種・動詞3語の外は書けない。

## 4. 値の形(取り違えが多いところ)

| キー | 形 |
|---|---|
| `columns` / `fields` / `search_fields` | **フィールドID(文字列)の配列**。1件以上。定義オブジェクトの配列ではない。`search_fields` は最大8件 |
| `sort` | `{ "field": "due_on", "order": "asc" }` **または**その配列。`field` と `order` の**両方が必須**。`order` は `asc` / `desc` |
| `filter` | **木**。葉は `{ "field": "...", "equals": ... }` の形で、`equals` / `contains` / `gte` / `lte` / `in` の**どれか1つだけ**を持つ。枝は `{ "and": [...] }` / `{ "or": [...] }` / `{ "not": {...} }` |

| `after_save` / `sum_field` | ID(文字列)1つ |

|---|---|
| `action_emphasis` | **ボタンの見た目の強さ。** `primary`(主)/ `secondary`(副)/ `danger`(危険)の3つから1つ。省略できる |

- **詳細画面(`detail_view`)のボタンにだけ書ける。** 一覧画面(`list_view`)の行のボタンに書くと差分全体が拒否される。
- **書かなかったボタンは副で描かれる。** **並び順で主が決まることは無い** —— 以前は、何も書かなくても1番目のボタンが主の見た目で出ていた。**主にしたいボタンには `primary` と書く**(以前と同じ見た目に戻る)。
- 4形(`form`+`prefill` / `set` / `view` / `run`)のどれとも一緒に書ける。**4形の排他は変わらない。**
- **詳細画面に元から在る「編集」「削除」のボタンの見た目は変わらない。**
- **選べるのは3つだけで、色そのものは書けない**(配色は今日どおりテーマから決まる)。

**`visible_when` の値は絞り込みの葉(`filter_leaf`)そのものである。**
**葉に書けるキーは6つ**(`field` / `equals` / `contains` / `gte` / `lte` / `in`)で、
**`field` が必須、残りの5つのうちちょうど1つを書く。** **枝(`and` / `or` / `not`)は1つも書けない。**
実物で見つかった形は `{ "field": "done", "equals": false }` と
`{ "field": "status", "equals": "active" }` の2つで、
**`equals` 以外の演算子を使った実物は、探した範囲では見つからなかった。**

**【混ぜないこと】ワークフローの `when` と同じ形ではない。**
**あちらは別の定義で、書けるキーは `field` と `equals` の2つだけ・両方が必須である。**
**「ワークフローの `when` と同じ」は今日は偽である。**
**同じなのは、どちらも `and` / `or` / `not` を1つも書けないという点だけである。**

**ボタンを隠すことは、書き込みを止めることではない。**

## 4a. 一覧画面の「新規作成」(宣言するキーは無い)

**一覧画面(`list_view`)には「新規作成」のボタンが自動で出る。** **このボタンを表すキーは1つも無く、書いて出すことも、書いて消すこともできない。**

出るのは、次の4つが**全部**そろったときだけである。

- 同じテーブルの `form` が在る(2本以上あるときは**定義順の先頭**の1本)
- その `form` がその人に見える(役割の規則で、その画面の読取が許されている)
- その人がそのテーブルへ書ける
- そのテーブルが `st_no_direct_create` を宣言していない

**押すと、その `form` の新規作成の画面が開くだけである** —— **一覧の絞り込みの値も、検索語も、1つも引き継がない。** **「この一覧では出さない」と画面ごとに書き分けることもできない**(消したいときは、テーブルの側に `st_no_direct_create` を宣言する)。

**行ごとの操作起点(`actions`)の「新規作成へ」とは別のボタンである** —— あちらは押した行の値を次の画面に渡すが、こちらは1つも渡さない。

## 4b. 一続きの流れ(`flow`)—— 段を宣言し、次の段へ進める

**一覧 → 入力 → 確認 → 完了 のように、画面をいくつか続けて通す道を宣言できる。**
**宣言するキーは `flow` の1本だけで、流れそのものを表す入れ物(「flow の一覧」のような
別の定義)は語彙のどこにも無い。**

### 値の形は3つだけ

```json
"flow": { "id": "apply", "step": 2, "kind": "input" }
```

| 鍵 | 何を書くか | 値域 |
|---|---|---|
| `id` | **その流れの名前**(画面のIDではない) | 文字列 |
| `step` | **その流れの中の位置** | **1から始まる整数**(0も負も小数も書けない) |
| `kind` | **段の種類** | **`input`(入力の段)/ `confirm`(確認の段)の2つだけ** |

**3つとも必須で、4つ目の鍵は無い。** 段の見出し・アイコン・色・所要時間・分岐の条件などを
書く場所は1つも無く、書いた差分は拒否される。

### 流れは「同じ名前の画面を位置の順に並べたもの」である

- **同じ `id` を書いた画面どうしが1つの流れになる。** **複数の画面が同じ `id` を持つのが
  正常であり、`id` の重複は拒否されない。**
- **並び順を書く場所は無い。** 並びは `step` から導かれる。
- **同じ `id` の中で `step` が重なっている差分は拒否される。**
- **同じ `id` の中で `step` が飛んでいる差分(1,2,4 のような欠番)も拒否される。**
- **`step` が 1 から始まっていない差分も拒否される。**
- **1段だけの流れは書ける**(その画面には次の段が無いので、次へは進まない)。

### 書ける種別

- **書けるのは一覧画面(`list_view`)・入力画面(`form`)・詳細画面(`detail_view`)の3種だけ。**
- **集計表(`report_view`)には書けない。** 書いた差分は拒否される。
- **確認の段(`kind: "confirm"`)にできるのは詳細画面だけである。**
  **入力画面や一覧画面に `confirm` を書いた差分は拒否される。**

### 宣言があれば段、無ければ今日どおり

- **段を宣言した画面では、次の行き先を決めるのは段の並びである。**
- **`after_save` と `flow` の両方を書いた画面では、段のほうが勝つ**
  (`after_save` は、段が解けなかったときにだけ効く)。
- **段を1つも宣言していない画面は、今日どおりの決まりで動く。**
  **`flow` を足しても、書かなかった画面の行き先は1バイトも変わらない。**
  - **【2026-08-21 訂正。上の2行は1バイトも消していない】**
    **1行目(段を宣言していない画面そのものの振る舞い)は今日も真である。**
    **偽になったのは2行目のほうである。** **`flow` を足すと、その画面を行き先にしていた
    別の画面の行き先が変わる** —— **一覧の行を押したとき・参照の項目のセルのリンク・
    子一覧の行の3つは、段を宣言した詳細画面を行き先の候補から外す。**
    **外した結果1枚も残らなければ、その行は押せない**(別の画面へは倒さない)。
    **段を1つも宣言していない画面の飛び先も、この形で変わる** ——
    同じ表に段になった詳細画面が在れば、そこへはもう飛ばない。
    **保存が成立したあとの行き先だけは今日も変わっていない。**

### 次の段へ進むきっかけ(**種別で違う**)

| その画面 | 次の段へ進むきっかけ |
|---|---|
| 入力画面(`form`) | **保存が成立したとき。**「次へ」のボタンは出ない(送信ボタンは今日も1つである) |
| 一覧画面(`list_view`) | **「次へ」のボタンを押したとき** |
| 詳細画面で `kind` が `input` | **「次へ」のボタンを押したとき** |
| 詳細画面で `kind` が `confirm` | **「次へ」は出ない。** その画面に書いた**値の書換のボタン**(`actions` の `set` の形)の書込が成立したとき |

**「次へ」のボタンが出るのは、次の全部がそろったときだけである。**

- その画面が段を宣言している
- その画面が入力画面(`form`)ではない
- その段の `kind` が `confirm` ではない
- **同じ流れの `step + 1` を宣言した画面が、そのアプリに実在する**(最後の段では出ない)
- **その画面が、見ている人に見える**(役割の規則で読取が許されている)

**1つでも欠ければボタンごと出ない。** **押せないボタンは出さない。**

**自動処理を起こすボタン(`actions` の `run` の形)では、段を宣言していても次の段へ
1ミリも進まない。** **進めるのは `set` の形だけである**(起動が受理されても処理が
失敗することがあり、進む時点で成否が確定していないため)。

**【隠さずに書く】`kind` が `input` の詳細画面に `set` の形のボタンを書くと、その書込でも
次の段へ進む。** そのとき同じ画面に「次へ」も出るので、**進み口が2つ並ぶ。**
**確認の段として使う画面には `kind: "confirm"` を書くこと。**

### 次の段へ運ばれるもの(**行1つだけ。しかも条件つき**)

- **運ばれるのは、次の段が「同じテーブルの詳細画面」のときの、いま扱っている行1件だけである。**
- **それ以外では何も運ばれない** —— 次の段が一覧画面・入力画面・別のテーブルの詳細画面の
  ときは、行も値も1つも渡らない。
- **前の段で入力した値は1つも運ばれない。** **確定していない入力を段のあいだで
  持ち回す仕組みは1つも無い**(途中の値を残したいなら、段ごとに行として保存する)。
- **一覧画面から進むときは、行を1件も指していないので何も運ばない。**

### 段を宣言すると自動で出るもの(**宣言する口は1つも無い**)

**段を宣言した画面には、こちらが1バイトも書かなくても2つのものが出る。**
**どちらも出し方・文言・位置を宣言する口は1つも無く、出すか出さないかも選べない。**

#### (1) いま何段目 / 全部で何段(**3種別すべてに出る**)

- **段を宣言した画面には `3段目 / 全5段` の形の表示が1つ出る。**
- **出るのは2つの数だけである。** 段の名前・種類(`input` / `confirm`)・進み具合の割合・
  残り時間は1文字も出ない。
- **押せない。** その表示から他の段へ飛ぶことはできない(飛べる目次ではない)。
- **段を宣言していない画面には1ピクセルも出ない。**
- **重ねて出す画面(`modal: true`)にも出る。** —— **そこには「戻る」は出ないので、
  重ねた画面では「いま何段目か」だけが出ることになる**(閉じる操作が既に履歴を1つ戻すためである)。
- **画面の名前(`name`)に段番号を手で書かないこと** —— **同じ数が2箇所に並び、
  あとで `step` を入れ替えたときに名前のほうだけが古い数のまま残る。**
  **この食い違いで赤くなる検査は1本も無いので、誰も気づかないまま残る。**

**いま何段目かは、同じ流れの画面を `step` の順に並べたときの順位である。**
**`step` の値そのものではない** —— 欠番のある古い定義が残っている場合、`step` の値と
表示される順位はずれる(新しく書く差分は欠番が拒否されるので、ふつうは一致する)。

**全部で何段かは、見る人によって変わることがある**(**隠さずに書く**):

| 見る人 | 総数に入る段 |
|---|---|
| ログインしている人 | **その人には開けない段も総数に入る。** 数は流れの宣言の全量と同じになる |
| ログインしていない人 | **見せると決めた段だけが総数に入る。** 同じ流れが小さい数に見える |

**どちらの数え方にするかを宣言する口は無い。**

#### (2) 「戻る」(**入力画面にだけ出る**)

**【2026-08-21 訂正。上の見出しと下の行は1バイトも消していない】**
**上の見出しの「入力画面にだけ出る」は、今日は偽である。**
**「戻る」は、段を宣言した画面には種別を問わず出る** —— **一覧画面にも、詳細画面にも、
入力画面にも、それぞれ1つ出る。** **今日の正はこの訂正のほうである。**
**出ないのは「段を宣言していない画面」と「重ねて出す画面」の2つだけである。**

- **段を宣言した入力画面(`form`)には、「戻る」のボタンが1つ出る。**
  - **【2026-08-21 追記】** **入力画面だけではない** —— **段を宣言した一覧画面と
    詳細画面にも、同じ「戻る」が1つ出る。** **確認の段(`kind` が `confirm`)にも出る。**
- **押すと、ブラウザの履歴を1つ戻る。**
- **戻り先を宣言する口は1つも無い。** 段の並びを1つ遡るのではなく、**履歴を戻るだけ**である。
- **URL を直接開いた場合は、履歴にその前の項目が無い。** そのときは押しても何も起きない
  (ボタンは出たままである)。
- **重ねて出す画面(`modal: true`)には出ない。** その器は閉じる操作が既に同じことをしている。
- **段1(`step` が 1)の画面にも出る。** そのときの行き先は流れの外である。
- **一覧画面(`list_view`)と詳細画面(`detail_view`)には出ない。** 出るのは入力画面だけである。
  - **【2026-08-21 訂正。上の1行は1バイトも消していない】** **その字面は今日は偽である。**
    **段を宣言した一覧画面と詳細画面にも「戻る」は1つ出る。** **段の位置でも段の種類でも
    分岐していないので、最初の段にも最後の段にも出る。**
    **出し方・文言・位置・出す出さないを宣言する口は、今日も1つも無い。**

**「次へ」とは向きが逆なだけの対ではない** —— 「次へ」は段の並びから次の画面を解いて進むが、
「戻る」は段の並びを1バイトも見ていない。

### 今日は書けないもの(**言い換えても書けない**)

- **ボタンの文言。** 「次へ」も、入力画面の送信ボタンも、文言は宣言できない。
- **流れの外へ出る行き先。** **流れは1つのアプリの中に閉じており、外部の URL も、
  別のアプリの画面も書けない。**
- **段の分岐**(条件で次の段を変える)。次は `step + 1` の1つだけである。
- **段のあいだで未確定の入力を持ち回すこと。**
- **段の見出し・アイコン・所要時間。**
- **位置と総数の表示の出し方・文言・位置。** 出すか出さないかも選べない。
- **「戻る」の文言と戻り先。** 履歴を1つ戻る以外の行き先は書けない。

## 5b. メニューの位置(`set_workspace`)—— 左か上か

- 位置の値は2つだけで、3つ目の置き場所(右・下など)や、画面ごとの位置は書けない。表・項目・画面・行には触れず、元に戻す(undo)で前の宣言に戻せる。

## 5c. マイページ(`workspace.my_page`)

「ログインした人が自分の情報と自分の記録をまとめて見られるページがほしい」「ログインしたらまず自分のページを開いて」と頼まれたら、`set_workspace` の2つ目のキー `my_page` で書く。 画面(`add_view`)を足すのではない。

```json
{ "op": "set_workspace", "workspace": { "my_page": { "open_after_login": true, "tables": { "exclude": ["memo"], "include": [{ "table": "tasks", "owner_field": "assignee" }] }, "views": ["order_form", "inquiry_list"] } } }
```

- **`my_page` があればマイページを置く。** 中の3キー(`open_after_login` / `tables` / `views`)はどれも省ける。 `{ "my_page": {} }` は既定どおり置く。 消すときは `{ "my_page": null }`。 4つ目のキーは書けない。
