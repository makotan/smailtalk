# 見た目の案をいくつか出して選んでもらうとき

この参照ファイルは、次のように頼まれたときに開く。

- 「見た目の案をいくつか出して」「どの形がいいか比べたい」「この画面をもっと見やすくして(案がほしい)」
- 「このスクショ(参考にしたい画面の画像)の色にして」「この色味に寄せて」(→ 7 節)

**ここに書いた出し方と手順は推奨である。** そう書かないと差分が止まる、という規則ではない。
**止まる条件(語彙の事実)は、推奨と分けて「断られる」と書いてある。**
**この出し方で良い案が出るとは約束しない。** どの案が良いかを決めるのは利用者である。

---

## 1. 案は構造の軸で振る(推奨)

案を2〜3出すときは、**並べ方・まとまり・区切りのような構造の軸で振る。**
**色だけ・余白だけが違う案を2つ出さない**(細部だけが違う案は、並べても選ぶ手がかりにならない)。

構造の軸として今日の語彙で書けるもの(書き方の全量は view-shape の説明書の §2 と [`view-keys.md`](view-keys.md) にある):

| 軸 | 語彙 | 書ける画面 |
|---|---|---|
| 1列に縦に積む | `layout` を書かない、または `layout` の `stack` | form / detail_view / カードの一覧 |
| 脇と本文に分ける | `layout` の `sidebar` | 同上 |
| 幅があれば横、無ければ縦 | `layout` の `switcher` | 同上 |
| 格子に並べる | `layout` の `grid` | 同上 |
| 項目を見出し付きのまとまりに分ける | `field_sections` | form / detail_view |
| 一覧を値ごとに区切る | `group_by` | list_view |
| 一覧を表かカードで見せる | `preset_list_shape`(`table` / `card`) | list_view |
| 項目を1段か2段に組む | `preset_field_columns`(`1` / `2`) | form / detail_view |

- **`layout` と `field_sections` を同じ画面に併記すると、差分全体が断られる**(語彙の事実)。 まとまりで分ける案と、並べ方の木で組む案は、別の案として出す。
- **一覧の `layout` は、その画面に `preset_list_shape: "card"` を書いたときだけ書ける**(語彙の事実。カードの中の並べ方になる)。

## 2. 各案に1行のトレードオフを付ける

見比べに出す案には、**その案を選ぶと何を得て何を手放すかを1行で付ける。**
粒度の例は「一覧性は高いが、狭い画面では縦に長い」程度でよい。

- **トレードオフは `dry_run_diff` の `compare.tradeoff` に書く。 書かないと断られる**(語彙の事実。1〜80字・改行なし)。
- **案の名前は `compare.name` に書く。 これも書かないと断られる**(1〜40字・改行なし)。
- 字数は1文字ずつ数える。

## 3. 見せる前に足切りする

**各案は、利用者に見せる前に `dry_run_diff` に渡す。**

- **拒否された案(検証に通らず、保存できない案)は落とす。** 直して出し直してよい。
- **注意(応答の `design_notices`)が付いただけの案は落とさない。 注意を添えて見比べに出す。** 注意は適用を止めない。
- リポジトリの手元で `bun run lint:design <マニフェストのファイル>` を打つと、同じ点検の注意が出る(注意があっても終了コードは 0)。
- **データが失われる操作(`remove_field` / `remove_table` / `change_table` / `change_field`)を1つでも含む差分は、見比べの束に入れられない**(語彙の事実)。 そういう変更は見比べに出さず、`dry_run_diff` で影響を確かめて利用者の同意を得てから `apply_diff` で適用する。

## 4. このアプリの型を既定にする

**`get_manifest` の `app.design_memory.patterns` に型(「このアプリのフォームは区切りのある1カラム」のような1文ずつ)があれば、それに沿う案を既定にする。**

- **型から外れる案には `compare.off_pattern: true` を付ける。** 見比べの画面に「このアプリの型と違う」と出る。
- **型の無いアプリで `off_pattern: true` を付けると断られる**(語彙の事実)。 型が無ければ、どの案にも付けない。
- **型を書く・外すのは、利用者に頼まれたときだけ。** 差分操作 `remember_design` の `design_memory.patterns` で丸ごと差し替える(10件まで・1件80字まで・同じ文を2度書けない。空の配列で全部外す)。
- **選んだ記録(`design_memory.choices`)は、見比べの画面で案を選んで適用したときに自動で残る。** 案の差分に `remember_design` の `choice` を書くと、その案は束に入らない(断られる)。
- **選んだときに書いた理由は、そのアプリにログインできる人なら誰でも読める。** 利用者に選んでもらう前に、そのことを伝える。

## 5. 選ぶ順番は、構造 → 部品 → 色(推奨)

**構造(並べ方・まとまり・区切り)→ 部品(ボタンの主副 `action_emphasis`・入力欄の幅 `field_width`)→ 色(テーマ `set_theme`)の順に相談する。**
**構造が決まる前に色の相談を始めない。** 色を先に決めると、構造を変えたときに見え方がまた変わる。

- 「誰がどんな場面で使うか」と「アプリの外枠(下のタブ・上のナビ)」を選ぶ場所は、今日の語彙に無い。 相談の段に入れない。

## 6. 見比べの束の書き方(語彙の事実)

1. **1案目**: `dry_run_diff` に差分と `preview`(`real` = 今のデータで描く / `sample` = 見本のデータで描く)と `compare`(`name` と `tradeoff`。`group` は省く)を付ける。
2. **2案目・3案目**: 1案目の応答の `compare.group`(`pv-` に続く16進32桁)を、そのまま `compare.group` に渡す。
3. **束の URL(応答の `compare.url`)を利用者に渡し、選んでもらう。** 直接 `apply_diff` しない。

- **1つの束は3案まで。** 束は最初の案を作ってから1時間で消える。
- 束に入れられるのは、同じアプリ・同じ人・同じ `preview` の値の案だけである。
- **束の URL は、URL を知っている人なら誰でも開ける。** 渡す相手を選ぶ。
- **並んだ案を選んで適用できるのは、ログインしていて、そのアプリの設定を変えられる人だけである。**
- **見比べの各枠は、各案のアプリの入口を開く。** 案が変えた画面は、その案の応答の `preview.url` から開ける。 利用者に見てほしい画面があれば、そのことも添えて伝える。
- `get_preview_url` が返す URL は見比べの束ではない(案を並べられない)。

## 7. スクショ(参考にしたい画面の画像)から色の案を出す手順(推奨)

「このスクショの色にして」と画像を渡されたときは、**色の案を2〜3作り、見比べの画面で選んでもらう。** 1案を直接適用しない。

1. **画像は会話の中であなた(AI)が読む。** アプリの自動処理から画像を AI に見せる口は、今日のこの製品には無い。
2. **読み取った色は推定であり、正しいとは限らない。** そのことを利用者に伝える。 「スクショの色を正確に写した」と言わない。
3. **構造がまだ決まっていないなら、色の相談の前に構造を決める**(5 節)。
4. **今のテーマを `get_manifest` で読む**(`app.theme`)。 `set_theme` はテーマを丸ごと差し替えるので、**各案で、役割の枠をすべて書く**(今のテーマから写し、変えたい枠だけ差し替える。テーマを持たないアプリでは全部の枠を自分で書く。1つでも欠けると断られる)。 **今のテーマに `slots_dark` があれば、それも全部書く**(書かずに差し替えると暗い側の配色が消える)。 枠の名前は、差分を書く道具の説明のテーマの段と、`get_manifest` が返す今のテーマで確かめる。
5. **`get_manifest` は生の色への参照(`$palette_名前`)を解かずにそのまま返す。** 実際の色を知るには、同じ組の中の `palette_名前` の値をたどる。 今のテーマを写すときは、参照と一緒に参照先の `palette_…` も写す。
6. **色の案を2〜3作る**(例: 読み取った色に寄せた案 / 文字と地の差を大きくして読みやすさを上げた案)。
   - 色は16進(`#rgb` / `#rrggbb`)か、明るさ基準の `oklch(L C H)` で書ける。
   - 同じ色を何か所にも使うときは、`palette_` で名付けた生の色にして、色の枠から `$palette_名前` で指してよい。 **`$palette_…` を書いたら、参照先の `palette_…` も同じ組(`slots` か `slots_dark`)の中に書く**(暗い側の組の参照は、暗い側の組の中の生の色しか指せない)。
7. **各案を `dry_run_diff` に渡す**(`preview` と `compare` を付ける。束の書き方は 6 節)。
   - `compare.name` は1〜40字、`compare.tradeoff` は1〜80字(どちらも改行なし)。 例: 名前「スクショの色に寄せた案」、トレードオフ「参考の画面に近いが、文字と地の差は小さめ」。
   - **読めない配色(文字と地のコントラストが足りない案)は断られる。 断られた案は落とす**(色を直して出し直してよい)。
   - このアプリに型(`design_memory.patterns`)が無いときは、どの案にも `off_pattern` を付けない(付けると断られる)。
8. **束の URL(`compare.url`)を利用者に渡し、選んでもらう。** 直接 `apply_diff` しない。 読み取った色が推定であることを、ここでも添える。
