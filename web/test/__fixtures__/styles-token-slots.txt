# ============================================================================
# テーマ対象外(3件)—— V3-M1-T03 の完了条件21(メインが実測して決めた)
# ============================================================================
#
# **上の28件のうち、次の3件は「アプリ単位テーマ」の対象に含めない。**
# したがって `schemas/manifest.schema.json` の `$defs/theme` の properties は
# **25キー**であり、`src/kernel/theme-contrast.ts` の役割表も25件である
# (ADR-0046 限定1 が言う3箇所一致は、この「**テーマ対象**スロット集合」で成り立つ ——
#  限定1 は `:root` の全スロットがテーマ対象であることを要求していない)。
#
# **3件は `:root` のスロットとしては残る**(上の28件から1件も減っていない)。
# したがって `web/test/styles.test.ts` の検査 (c) / (d) / (e) は緑のままである。
#
# **この節を増やすことは「テーマで指定できない項目を増やす」ことであり、
# ADR-0046 §3a の門を通す事項である。** 増減は差分に必ず出る(照合検査が
# (i) テーマ対象25件の一致と (ii) 対象外3件の一致の両方を固定する)。
#
# theme-excluded: --shell-max-width
#   `.shell` だけが参照する。**`.shell` はアプリ単位スコープ要素の外側である**
#   (シェルは V3-M3 / D-G6 の担当)。テーマに入れても値を埋めて画面が
#   1ピクセルも変わらない = 憲法6 に触れる(T01-7 で処置した死んだ3スロットと同型)。
# theme-excluded: --border-style
#   `.shell header` と `.list-table th, td` が参照する。**7軸に「枠線の種別」は
#   含まれない**(軸は 角丸 / 影 / アウトライン / ページ地色 / 本文文字色 / 密度 /
#   枠線の強さ)。enum を `["solid"]` の1値にすると「埋めても変わらないスロット」に
#   なり、`dashed` 等を許すと T01 が失った表現力を復活させる = 7軸を超える増分になる。
# theme-excluded: --focus-outline-style
#   `:focus-visible` が参照する。同上(種別は軸に含まれない)。
